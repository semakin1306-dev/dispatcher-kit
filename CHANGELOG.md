# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [семантические](https://semver.org/lang/ru/); пока версия 0.x, несовместимые изменения возможны и в младших версиях — они отмечаются в разделе «Изменено» словом **несовместимо**. ## [Unreleased]

### Добавлено

- **Несколько проектов на одной диспетчерской: дом и хаб.**
  - Дом — файл `dispatcher.home.json`. В нём общее для проектов: агент по умолчанию, машины, общий предел агентов слотов и порт хаба. Там же список проектов: у каждого свой конфиг прежнего формата и свой порт. Без дома всё работает как раньше.
  - `node setup.mjs add --repo <путь> [--id <id>] [--light]` проводит те же detect, вопросы и apply. Конфиг ложится в `projects/<id>/`, проект вписывается в дом. Первый `add` создаёт дом, а прежний `dispatcher.project.json` входит в него ссылкой, без переноса. Ещё есть `setup.mjs list` и `setup.mjs remove --id`.
  - `setup.mjs doctor` в доме проверяет дом и каждый проект, а также то, что проекты не делят: папки, клон на удалённой машине и бота Телеграма.
  - Удалённая машина из дома даёт каждому проекту свою папку `<dir>/<id>`.
  - Команды эпиков (`epic.mjs`, `slot-up.mjs`, `fleet.mjs` и другие) принимают `--project <id>`. Если команда запущена из папки проекта, проект выбирается сам.
- **Хаб** `node scripts/dev/hub/server.mjs`.
  - Слушает порт 4777 и поднимает по процессу на проект, каждый на своём порту.
  - Пересылает в нужный процесс страницу (`/p/<id>/`) и `/api/*`, отдаёт сводку `/api/summary` и страницу-список.
  - Перезапускает упавший процесс с паузами. При выходе снимает все процессы с деревом потомков: на Windows через `taskkill /T`, на Linux и macOS через обход дерева.
  - Проект с `"start": "lazy"` поднимается по запросу и останавливается без дел.
  - Безопасность как у ядра: только 127.0.0.1, проверка Host, свой токен страницы на изменения.
  - Ядро о доме не знает, а хаб не загружает проект ядром. Это проверяет сторож в `imports.test.mjs`.
- **У ядра маршрут `/api/summary`:** короткая сводка процесса проекта (эпики, агенты, прогоны, ждущие вопросы, память, простаивает ли).
- **Предел агентов слотов работает.** Ключ `limits.slots` раньше только спрашивался квизом. Теперь сверх предела агент слота не запускается: отказ называет, кто занят и какой ключ поднять. Если есть молчащий агент, он уступает место: останавливается, а сессия сохраняется. В доме действует ещё и общий предел на все проекты (`shared.limits.slots`): места-файлы в папке хаба, место упавшего процесса не держится. Оркестратор и агент бэклога в предел не входят.
- **Ключ `mode` в конфиге проекта** (`full` | `light`) и флаг `--light` у `setup.mjs add`. Лёгкий режим в разработке: пока проект ведётся как полный.

### Исправлено

- **Уборка папок слотов трогает только своё.** Уборка на странице (`/api/hygiene`) считала лишней любую рабочую копию репозитория, которая не нужна открытому эпику: копию, заведённую человеком рядом с проектом или внутри папки слотов, папку бэклога `_backlog` и папку поезда `regress-train`. Такие копии уходили в `git stash` и удалялись. Теперь «моё» определяет одно правило (`scripts/dev/ownership.mjs`): только прямые дети `repo.worktrees` с именем по правилу диспетчерской (`wv<NNNN>-…`, `tr-…`, `epic-…`) или из реестра эпиков. Служебные папки (`_…`, `regress-…`) не убираются, основная папка проекта и всё вне папки слотов не предлагаются никогда. Чужие копии план показывает отдельно, не трогая. Тем же правилом идёт `epic.mjs close --remove-worktrees`: папку оркестратора вне папки слотов оно больше не снимает. Сторож в `ownership.test.mjs` ловит новое удаление папок мимо правила.
- **Linux и macOS: снятие дерева процессов.** Остановка агента, отмена прогона, кнопка «остановить процесс» и `tools/restart-dashboard.mjs` посылали сигнал только самому процессу, а его дети (тесты, сборки, инструменты агента) оставались жить. Теперь обходится всё дерево по таблице процессов (`/proc` на Linux, `ps` на остальных системах), глубокие — первыми. На Windows по-прежнему `taskkill /T`.
- **Сравнение путей по файловой системе, а не строкой.** Короткие имена Windows (`RUNNER~1`), ссылки и junction в `repo.worktrees`, `/var` и `/private/var` на macOS давали два разных написания одной папки. Из-за этого уборка слотов могла счесть все слоты лишними и убрать их папки (`stash` и `git worktree remove`), повторный запуск подготовки слота отвечал «уже занят», а повторная установка хука слота могла запомнить папку хуков слота как папку проекта. Теперь пути раскрываются через `realpath`, регистр не различается на Windows и macOS.
- **macOS: свободная память.** `os.freemem()` на macOS считает только совсем свободные страницы, и проверка памяти перед запуском агента, места своей машины и предел дорожки подготовки не пускали ничего. Теперь доступная память считается по `vm_stat` (свободные, спекулятивные и неактивные страницы).
- **Рецепт подготовки слота:** сказано, какой оболочкой выполняется шаг (`cmd.exe` на Windows, `/bin/sh` на остальных) и как писать кавычки, чтобы команда работала в обеих.
- **Тесты:** исправлены тесты, которые падали только на Linux и macOS (кавычки в команде шага, уборка процессов без `taskkill`, проба удалённой машины без `/proc`).
- **Находки при комментировании кода** (иссью #1):
  - подсказка оркестратора о «ВЛИТЬ ПN ПРИНУДИТЕЛЬНО» теперь называет все снимаемые проверки: регресс, ревью, гарды и доклад «ГОТОВО» по вагону поезда, как в коде (`FORCE_SOFT`); отказ команды перечисляет то же; тест сверяет подсказку с кодом;
  - коммит силами агента не отправляет просьбу агенту, который дольше 20 минут занят своим ходом: задача коммита падает с причиной «занят своим ходом… просьба не отправлена»;
  - журнал автопередач между агентами убирает пары без передач за последний час, а не растёт до перезапуска;
  - «план волны есть» больше не срабатывает на файл с номером волны, но не `.md`: три поиска плана сведены в один;
  - станции «В staging», «На стенде», «В проде» и снимок находят влив ветки по точному имени из темы merge-коммита: ветка `dev/wv-0001-a` больше не «влита» вливом `dev/wv-0001-ab`, а у поезда показывается влив своего вагона;
  - влив зелёным поездом без записи прогона или с удалённым слотом состава отвечает «не годен» с причиной, а не падает с TypeError;
  - в причине толчка автопоезда у станции без названия стоит её id, а не `undefined`;
  - убран неиспользуемый экспорт `pairConflict`, локальная переменная в `relayNow` больше не перекрывает импорт `prompt()`.
- **Передачи между агентами без артефактов контекста.** Агенту приходит только намеренное сообщение и факты диспетчерской:
  - решение слота «ДАЛЬШЕ: ОРКЕСТРАТОРУ» (или «СЛОТУ ПN») без блока ```text больше не отправляет вместо доклада весь ответ агента: рассуждения, пересказ инструментов и последние 6000 знаков, обрезанные посреди фразы. Передачи нет, агенту слота уходит короткая просьба оформить доклад блоком (подсказка `relay-no-block`, не чаще раза в 10 минут), в журнал — событие `relay.noblock`. Если блок был, но его отсеял фильтр «оркестратору нечего передавать», явное решение слота сильнее фильтра: уходит ровно этот блок. Уже переданный блок повторно не шлётся;
  - подпись происхождения правдива. Раньше любая передача, и автоматическая, начиналась словами «передан кнопкой дашборда». Теперь «кнопкой владельца» пишется только для кнопок страницы; решение «ДАЛЬШЕ: …» подписывается «по решению самого отправителя», автопоезд, очередь и передача после подготовки слота — «диспетчерской автоматически». Происхождение едет с карточкой через очередь, ожидание подготовки и пачку оркестратору (у каждого доклада пачки своя подпись). Подписи собраны в одном месте (`RELAY_VIA`, заголовки — подсказки `relay-head-*`), начало «Ответ слота …» для правила `orchWake` не изменилось. Персона инженера слота больше не опирается на слова «кнопкой дашборда»;
  - вводная новой сессии оркестратора после ротации больше не несёт три последних ответа старой сессии, обрезанных на 1500 знаках, и два сообщения владельца, обрезанных на 800: обрывки читались как действующие решения. Вместо них — факты диспетчерской: строка о каждом слоте эпика по снимку (влит ли, коммиты, станции, агент, ждущие передачи), открытые вопросы владельцу и тупики правил, ожидания влива по слову владельца и, целиком, сообщения владельца, на которые старая сессия не ответила;
  - копилка «Попутно» знает предмет сведения (слот + вид + прогон): новое сведение о том же предмете заменяет старое, а при выдаче выбрасываются сведения о слоте, которого больше нет, и отказы ворот по уже влитому слоту;
  - ревьюер второго круга получает доклад автора блоком, а не хвост всего его хода с обрезанным началом; эскалация ревью оркестратору подписана диспетчерской и несёт доклад автора, а не ссылку «доводы в его последнем ответе», которого оркестратор не видит;
  - обрезы в сообщениях агентам — только с пометкой «…»: выжимка лога в справке и итогах прогонов, сводка прогона в справке, красное для ожидания влива, неисполненные команды оркестратора больше не режутся посреди строки молча. Сторож в `relay-context.test.mjs` проверяет функции сборки сообщений на обрез без пометки и точный состав сообщения передачи.
- **Тесты не зависят от часового пояса машины.** Эталон подсказок (`prompts.test.mjs`) падал на раннерах CI в UTC: окно эпика в подсказке ретро пишется местным временем, а эталон был снят в UTC+1. Тест закрепляет `TZ=UTC`, эталон переснят; тест карточки бэклога берёт местный полдень вместо полудня UTC (в UTC+14 это уже другая дата). Весь набор проверен в поясах от UTC−12 до UTC+14.

### Изменено

## [0.1.0] — 2026-11-24

Первая публичная редакция.

### Добавлено

- **Эпики, волны, слоты и поезда:** у каждой задачи своя рабочая копия (git worktree), своя ветка `dev/wv-NNNN-…` и строка `Wave: WV-NNNN` в коммитах (хук слота); поезд — очередь волн одной области. Команда `scripts/dev/epic.mjs`, подготовка слота `scripts/dev/slot-up.mjs`.
- **Страница** на `127.0.0.1:4777`: слоты, станции волны, прогоны проверок, чаты агентов, вопросы владельцу, влив в staging кнопкой, журнал событий.
- **Агенты:** оркестратор эпика, инженер слота, разовый ревьюер; Claude Code — постоянный процесс со stream-json и вопросами разрешений на страницу; адаптер Codex CLI — экспериментальный, вживую не проверен.
- **Запреты слота** из конфига (`deny`, `areas.*.denyEdit`): пуш, перезапись истории, переключение веток, `git add -A`, `ssh`/`scp`, чтение `.env`.
- **Стартовая настройка** `setup.mjs` (`detect`, `apply`, `doctor`): агент по `SETUP.md` определяет стек, области, ветки и CI, задаёт вопросы и собирает `dispatcher.project.json`; навыки агента раскладываются в каталог пользователя.
- **Модули** (включаются в конфиге): `review`, `backlog`, `retro`, `machines` (прогоны на других машинах по ssh), `release` (выкат стенда и прода), `accept` (приёмка на стенде), `tg` (Телеграм-бот вопросов), `win-desktop` (ярлыки и раскладка окон Windows).
- **Переключатели поведения** на странице настроек: автокоммит, автовлив, автопоезд и другие; по умолчанию всё ручное.
- **Код-надстройка** `dispatcher.project.mjs` с закрытым списком функций и **рецепты** в `docs/recipes/`.
- **Ворота публикации** `tools/publish-check.mjs`: адреса, личные пути, почта, ключи и список частных слов.
- **CI** на GitHub Actions: тесты на Ubuntu, macOS и Windows с Node 22 и 24, ворота публикации.
