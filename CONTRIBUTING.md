# Как участвовать

*English: issues and pull requests in English are welcome. Code, comments, UI texts and docs stay in Russian — see «Язык» below.*

Спасибо, что заглянули. Ниже — что нужно знать до первого pull request.

## Тесты

Зависимостей нет: нужен только Node 22 или новее и git 2.31+. Из корня репозитория:

```
node --test
```

Тесты идут на демо-конфиге `test/fixtures/project.demo.json`, поднимают временные репозитории и поддельный рантайм агента (`test/fixtures/fake-claude.mjs.tpl`). Настоящие `claude` и `codex` не запускаются, ваш проект и профиль не трогаются: навыки под `node --test` в `~/.claude/skills` не пишутся.

Несколько тестов пропускаются сами: проверка областей видимости страницы — без разборщика acorn (путь к нему — переменная `DK_ACORN`), проверка прав файла `0600` — на Windows, обход таблицы процессов этой машины — тоже на Windows (там дерево процессов снимает `taskkill /T`).

CI гоняет `node --test` на Ubuntu, macOS и Windows с Node 22 и 24 (`.github/workflows/ci.yml`). Если правка зависит от ОС — путей, оболочки, процессов, памяти, — проверьте, как она поведёт себя на остальных двух.

Документы тоже под тестами: `test/docs.test.mjs` сверяет таблицы README с каталогом модулей и переключателями, ключи конфига в README и рецептах — со схемой. Добавили модуль, переключатель или ключ — допишите документ, иначе тест покраснеет.

Указания агенту живут в одном файле — `AGENTS.md` (его читает Codex). `CLAUDE.md` состоит из одной строки `@AGENTS.md`: Claude Code подставляет по ней файл целиком. Правьте `AGENTS.md`; тест проверяет, что `CLAUDE.md` остался импортом.

## Ворота публикации

```
node tools/publish-check.mjs --ci
```

Ворота ищут в репозитории IP-адреса, личные пути вида `/home/<имя>`, почту и ключи. Без `--ci` они требуют ещё и файл частных слов `.private-denylist` в корне (он вне git) и без него отказывают — так задумано для сопровождающего. Контрибьютору хватит `--ci`: это тот же набор общих правил, что в CI. Если хотите проверить и свои имена, хосты или домены — создайте свой `.private-denylist` (по строке на слово или `/регулярку/`) и запускайте без `--ci`.

Ложная находка, которая нужна в тексте, снимается пометкой `publish-check: allow` в той же строке с причиной рядом.

## Язык

- Код, комментарии, тексты интерфейса, сообщения об ошибках, документы — **по-русски**. Имена в коде — латиницей, как обычно.
- Иссью и pull request можно писать по-английски.

## Правила кода

- **Без зависимостей.** Ни `package.json`, ни `npm install`: только встроенные модули Node. Если без пакета никак — сначала иссью.
- **Окончания строк — LF** (кроме пускателей Windows `.bat`, `.cmd`, `.ps1` — там CRLF). Это закреплено в `.gitattributes`.
- **Ядро не знает чужого проекта.** Всё, что относится к конкретному проекту, — в `dispatcher.project.json` и `dispatcher.project.mjs`, а не в коде. Нужен новый ключ — добавьте его в схему (`scripts/dev/project.mjs`), в демо-конфиг и в документ.
- **Безопасные умолчания.** Новое поведение, которое коммитит, вливает, пушит или выкатывает, по умолчанию выключено. Выкат и пуш в прод-ветку — только кнопкой человека.
- **Тест на правку.** Исправление ошибки приходит с тестом, который без исправления падает.
- **Строки не длиннее 200 знаков** в `.mjs`. Это проверяет `test/code-style.test.mjs`; редкие исключения (длинные регулярки) перечислены в `test/fixtures/long-lines-allow.txt`.
- **Тексты подсказок агентам — в `scripts/dev/prompts/*.md`**, не в коде. Подставляются помощником `prompt(name, vars)` из `scripts/dev/prompts.mjs`. Итоговые тексты сверяются с эталоном `test/fixtures/prompts-golden.json`; правите подсказку намеренно — перезапишите эталон: `DK_PROMPTS_GOLDEN=write node --test scripts/dev/prompts.test.mjs` и проверьте дифф эталона глазами.

## Codex не проверен — PR приветствуются

Адаптер Codex CLI (`scripts/dev/runtimes/codex.mjs`) написан по документации и проверен только контрактным тестом на поддельном бинарнике: автор пользуется Claude Code. Если вы работаете с Codex — запустите, расскажите, что сломалось, или пришлите исправление. Известные ограничения — в README, раздел «Codex — экспериментально», и в [рецепте](docs/recipes/codex.md). Так же приветствуются проверки и правки для Linux и macOS: вживую там диспетчерской не пользовались.

## Где что лежит

| Путь | Что там |
|---|---|
| `scripts/dev/` | ядро: конфиг проекта (`project.mjs`), каталог модулей, эпики (`epic.mjs`), подготовка слота (`slot-up.mjs`), адаптеры рантаймов (`runtimes/`), хук слота (`hooks/`) |
| `scripts/dev/dashboard/` | сервер страницы (вход — `server.mjs`, сборка — `boot.mjs`, маршруты — `http.mjs`), агенты, прогоны, модули; сама страница — `index.html` и `ui/` |
| `setup.mjs`, `setup/` | стартовая настройка: определение фактов о проекте, вопросы, сборка конфига, навыки, `doctor` |
| `skills/` | навыки агентов; настройка раскладывает их в каталог пользователя |
| `agent-briefs/` | шаблоны указаний агентам: общие правила сессий эпика и персона инженера слота |
| `docs/recipes/` | рецепты: как подогнать диспетчерскую под проект |
| `tools/` | ворота публикации, безопасный перезапуск сервера и мелкие инструменты |
| `test/` | сквозной тест, сторожа документов, демо-конфиг; тесты модулей лежат рядом с модулями (`*.test.mjs`) |
| `desktop/` | пускатели Windows (модуль `win-desktop`) |
