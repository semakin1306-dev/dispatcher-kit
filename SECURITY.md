# Безопасность

*English: please report vulnerabilities privately via GitHub (Security tab → Report a vulnerability), not in a public issue. Reports in English are welcome.*

## Как сообщить

Через закрытое сообщение GitHub: вкладка **Security** репозитория → **Report a vulnerability**. Его видят только сопровождающие.

Не открывайте публичный иссью и не присылайте pull request с исправлением, пока о находке не договорились: публичный текст — инструкция для чужих рук до того, как вышло исправление.

Что приложить: версию (`git describe --tags --always`), ОС и версию Node, рантайм агента (Claude Code или Codex), шаги, которые воспроизводят находку, и что именно вышло за границу.

## Чего ждать

Проект ведёт один человек в свободное время. Ответ и исправление — по возможности, сроков не обещаем. Подтверждённую находку исправим, опишем в [CHANGELOG.md](CHANGELOG.md) и, если вы не против, назовём вас в описании.

## Что считается уязвимостью

Диспетчерская запускает агентов, которые правят файлы и зовут команды, поэтому граница для неё — запреты, которые она обещает держать. Уязвимость — когда граница не держит:

- **Обход запретов слота.** Агент слота выполнил то, что закрыто: пуш, перезапись истории, переключение веток, `git add -A`, `ssh`/`scp`, чтение `.env`, правку путей из `deny` или `areas.*.denyEdit`, коммит без разрешения — и это прошло мимо проверки диспетчерской, а не по вашим собственным разрешающим правилам.
- **Запись вне слота.** Агент слота или прогон записал в основную папку проекта, в чужой слот, в папку самой диспетчерской или куда-то ещё за пределами своих папок.
- **Доступ к странице не с этой машины или без токена.** Сервер ответил на запрос не с `127.0.0.1`, принял запрос с чужим `Host` или выполнил действие (`POST`) без токена страницы. Сюда же — чужой сайт, открытый в браузере, сумел заставить страницу что-то сделать.
- **Утечка секретов.** Токен бота или другой секрет попал в журнал, на страницу, в командную строку процесса, в текст агенту или в репозиторий.
- **Выполнение команд из недоверенного ввода.** Текст из Телеграм-бота, поле страницы, имя ветки или слота, вывод тестов или ответ агента превратился в команду оболочки или аргумент, которого не должно было быть. Сообщения в бот от чужого чата или пользователя приняты как ответ человека.
- **Ворота публикации пропускают то, что обещают ловить** (адреса, личные пути, почту, ключи) — если из-за этого секрет может уйти в публичный репозиторий.

## Что уязвимостью не считается

- То, что агент делает в пределах прав, которые вы ему дали: включённый переключатель `fullPermissions`, ваши разрешающие правила в `~/.claude/settings.json` (агенты Claude Code запускаются с пользовательскими настройками — см. README, раздел «Что setup делает с вашей системой»), ответ «разрешить» на странице.
- Команды из вашего `dispatcher.project.json` и функции `dispatcher.project.mjs`: конфиг — ваш код, диспетчерская выполняет его как есть.
- Действия программ и пользователей на той же машине: они считаются доверенными (см. модель угроз).
- Известные ограничения Codex: запреты слота там держатся в основном текстом подсказки, песочница закрывает только запись вне слота и сеть. Это описано в README.
- Уязвимости самих Claude Code, Codex CLI, git или Node — о них сообщайте их авторам.

## Модель угроз кратко

- **Сервер слушает только `127.0.0.1`** (`scripts/dev/dashboard/config.mjs`, `HOST`; порт — `DASH_PORT`, по умолчанию 4777). Входящих портов наружу нет; Телеграм-бот сам опрашивает Telegram с этой машины.
- **Проверка `Host`.** Запрос с заголовком `Host`, отличным от `127.0.0.1:<порт>` и `localhost:<порт>`, получает 403 (`okHost` в `scripts/dev/dashboard/http.mjs`). Это закрывает подмену DNS (DNS rebinding): чужой сайт не может выдать себя за страницу.
- **Токен на запись.** При каждом запуске сервер выбирает случайный токен и вставляет его в страницу; всякий `POST` без заголовка `x-dash-token` с этим токеном получает 403. Токен защищает от чужих сайтов в браузере (подделка запроса), а не от программ на этой же машине: любая местная программа может открыть страницу и прочитать его. Чтение состояния (`GET`) токена не требует.
- **Бот** принимает ответы только от chat_id и user id, закреплённых при настройке; ответ из бота даёт право только на ответ агенту, коммит и влив в staging. Выкат, пуш в прод-ветку и «принудительно» — только со страницы.
- **Секреты** (токен бота) берутся из переменной окружения `DISPATCHER_SECRET_<ИМЯ>`, из файла в папке данных (на POSIX — только с правами `0600`) или, на Windows, из файла, зашифрованного DPAPI. Значение не печатается и не передаётся в командной строке.
- **Агенты** запускаются без обхода разрешений: у Claude Code — `acceptEdits` и вопросы на страницу через `--permission-prompt-tool=stdio`, запреты слота — в `.claude/settings.local.json` рабочей копии; у Codex — песочница `workspace-write`, у разовых агентов — `read-only`.
