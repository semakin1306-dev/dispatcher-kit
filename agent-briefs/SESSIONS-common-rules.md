# Общие правила сессий-исполнителей (шаблон эпика)

Шаблон диспетчерской. Новый эпик кладёт копию в `.claude/plans/waves/agent-briefs/SESSIONS-common-rules.md` своей папки, только если такого файла в репозитории проекта ещё нет; если есть (база правил проекта) — не заменяет его, а дописывает своё в разделы «Известное, не чинить» и «Правила эпика». Разделы «Первые шаги» и «Проверки» не переписывай: окружение слота и проверки делает диспетчерская.

Прочитай целиком до первого действия. Этот файл — общее; план волны указан в стартовом сообщении.

## Модель веток

- **`staging`** — интеграционная линия и кандидат в выпуск (в проекте за ней стоит его интеграционная ветка). Ветка волны `dev/wv-NNNN-<имя>` срезана **от `staging`** — её заводит диспетчерская, сам ветки не режешь.
- Вливает ветку волны в `staging` диспетчерская по слову владельца (`merge --no-ff`, один merge на волну). Ты сам не вливаешь, не пушишь `staging` и `main`.
- **`main`** — прод-ветка (если она в проекте есть); её не трогаешь вовсе. В `staging` попадает только законченное; недоделанное — за флагом.

## Где ты

Ты в **своей папке слота** на **своей ветке** волны (путь — в подсказке «ГДЕ ТЫ РАБОТАЕШЬ»). Основная папка проекта — не твоя: staging читай через `git show staging:<путь>`.

## Первые шаги (один раз)

1. `git status` и `git branch --show-current` — убедись, что это твоя ветка. Локальные файлы окружения (`.env` и подобные) уже на месте и в git не идут.
2. Прочитай план своей волны (путь — в стартовом сообщении).
3. **Ничего не ставь и не собирай.** Подготовку слота (зависимости и прочее) делает диспетчерская по шагам из конфига проекта; сборку и проверки — станции. Если в папке слота что-то не собрано, проверки в ней дадут ложное красное — это не поломка и не повод для СТОП.

## Проверки

- Сборку, гарды, тесты и регресс гоняет **диспетчерская станциями** и присылает итог с выжимкой. Сам их не запускаешь.
- Нужна проверка, которой ещё не было, — в докладе раздел «Нужно от оркестратора:» со строкой `ПРОГНАТЬ ПN: задача=фильтр` (id задачи — из каталога задач диспетчерской), и продолжай работу.
- Итог прогона разбирай по правилам из сообщения диспетчерской: своё чинишь сразу, чужое — оркестратору.

## Что делать нельзя

- **Трогать файлы вне манифеста** своей волны (границы записаны в запретах слота). Нужен чужой файл — запрос оркестратору, не правь.
- Общие файлы проекта (манифесты пакетов, файлы блокировок, общие конфиги, описание CI) — только оркестратор; их список — в запретах слота и в «Правилах эпика».
- **`git push`, слияния, выкат — никогда**; коммит — по правилу КОММИТ в подсказке диспетчерской. `git add -A` и `git add .` не использовать: только список своих файлов.
- Прод-ветку не трогать: в некоторых проектах пуш в неё сам выкатывает прод.

## Что приносить в конце хода

Станции плана проходишь подряд в одном ходе; доклад — один, в конце: когда сделано всё, что можно без чужого решения, или когда заблокирован каждый оставшийся кусок. Промежуточных докладов по станциям нет.

В журнал (строка внизу плана волны) и в доклад: что сделано; какие файлы изменены (список); какие спеки добавлены; какие проверки нужны (`ПРОГНАТЬ …`); что передано соседу; что взято «по умолчанию»; открытые вопросы. Затем ждать итог станций.
