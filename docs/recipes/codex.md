# Codex вместо Claude Code

## Статус

Адаптер Codex CLI (`scripts/dev/runtimes/codex.mjs`) написан по документации и исходникам Codex CLI и **вживую не проверялся**: автор диспетчерской пользуется только Claude Code. Проверен он контрактным тестом на поддельном бинарнике (`scripts/dev/runtimes/codex.test.mjs`) — то есть флаги запуска и разбор событий совпадают с тем, что описано в документации, но не обязательно с вашей версией Codex. `node setup.mjs doctor` и чат агента напоминают об этом.

Обходов для ограничений ниже (например, ротации контекста оркестратора без счётчика токенов) в диспетчерской нет и пока не планируется — пробуйте свои.

## Как подключить

1. **Поставьте Codex CLI** и войдите в аккаунт — в обычном терминале, не из диспетчерской:

   ```
   npm install -g @openai/codex
   codex login
   ```

   Проверьте, что команда есть в PATH: `codex --version`. Если Codex стоит не в PATH — путь к нему пишется в `agent.bin`: полный, `~/…` (от домашней папки) или относительный (от папки конфига). Голое имя, например `codex-beta`, ищется в PATH. На Windows сначала ищется `codex.exe`, потом обёртка npm `codex.cmd` (тогда запускается её скрипт через node).

2. **Выберите рантайм** в `dispatcher.project.json`:

   ```json
   "agent": {
     "runtime": "codex",
     "network": false,
     "models": { "orch": "", "slot": "", "review": "" }
   }
   ```

   Стартовая настройка ставит `agent.runtime: "codex"` сама, если в PATH есть `codex` и нет `claude`, иначе спрашивает.

3. **Модели.** `agent.models` — модель для каждой роли: оркестратор (`orch`), инженер слота (`slot`), ревьюер и ретро (`review`). Имя — как его понимает `codex -m`; пустая строка — модель Codex по умолчанию.

4. **Сеть.** `agent.network` — выход в сеть из песочницы (подробнее ниже). По умолчанию выключен.

5. **Навыки.** `node setup.mjs apply` раскладывает навыки диспетчерской в `~/.agents/skills/<имя>/SKILL.md` — там их ищет Codex. Свой каталог — переменная `DISPATCHER_SKILLS_DIR`. Чужой навык с тем же именем не перезаписывается.

6. **Проверьте установку:** `node setup.mjs doctor`. В строке «Агент» должны быть `codex`, путь и версия; предупреждение об экспериментальной поддержке — ожидаемое.

`agent.proxy` — прокси до провайдера модели, если он нужен.

## Как устроен адаптер

- Каждый ход агента — отдельный запуск `codex exec --json` в папке слота, с песочницей `workspace-write`. Продолжение беседы — `codex exec … resume <id беседы>`.
- Сообщения, пришедшие во время хода, копятся и уходят следующим ходом одним заданием.
- Подсказка роли (оркестратор, инженер слота) идёт началом первого задания беседы: отдельного флага системной подсказки у `codex exec` нет.
- Разовые запуски (ревью, ретро) — песочница `read-only`.
- История чата — собственная запись событий диспетчерской в папке данных (`codex-sessions/`), а не файлы сессий Codex.

## `agent.network`

Песочница `workspace-write` по умолчанию без сети. Если агенту нужно ставить пакеты или читать документацию в сети — `"network": true` (адаптер передаёт `-c sandbox_workspace_write.network_access=true`). Claude Code этот ключ не читает.

С выключенной сетью заодно не проходят `git push`, `ssh`, `scp` — это часть защиты, раз запреты держатся в основном текстом (ниже).

## Известные ограничения

- **Запреты держатся в основном текстом.** У `codex exec` нет списков разрешений и запросов на инструмент. Адаптер пишет запреты в `AGENTS.override.md` в корне папки слота (вместе с копией `AGENTS.md` проекта) и прячет файл через `info/exclude`. Запрещённые команды, «спрашивать перед коммитом», запрет правки путей внутри слота и чтения `.env` агент соблюдает по этому тексту.
- **Песочница реально закрывает только две вещи:** запись вне папки слота и сеть.
- **Коммит силами агента может не пройти.** Папка git рабочей копии лежит вне папки слота, а песочница открывает её только на чтение. Оставьте режим коммита `word` и коммитьте кнопкой.
- **Счётчик контекста — 0** (`ctxTokens`): Codex не сообщает расход, поэтому ротация оркестратора по токенам не срабатывает. Следите за длиной беседы сами.
- **Нет запросов разрешений и потока текста.** Ответ появляется целиком в конце хода; политика разрешений диспетчерской у Codex не вызывается.
- **Прерывание.** На Linux и macOS — SIGINT, через 5 с снятие процесса; на Windows — сразу снятие дерева процессов. Отложенные сообщения не сбрасываются и уйдут со следующим.
- **Агент бэклога** получает `workspace-write` на дереве: «ничего не править» держится подсказкой и перемоткой дерева.

## Если не заработало

- `node setup.mjs doctor` — найден ли `codex`, какая версия.
- Сверьте флаги со своей версией: `codex exec --help`. Адаптер ставит `-s`, `-C`, `-m` до `resume` и задание передаёт через stdin (`-`).
- Нет входа в аккаунт — Codex сам об этом скажет в выводе первого хода; войдите командой `codex login` в обычном терминале.
- Адаптер и его контрактный тест — `scripts/dev/runtimes/codex.mjs`, `scripts/dev/runtimes/codex.test.mjs`. Разбор событий и флаги запуска собраны в начале файла адаптера.
