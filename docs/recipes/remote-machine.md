# Удалённая машина прогонов

## Когда нужна

На этой машине работают агенты, редактор и сама диспетчерская; тяжёлые тесты рядом с ними тормозят всё. Модуль `machines` отправляет прогоны задач на другие машины по ssh: свой сервер сборки, свободный компьютер, свой раннер CI.

## Что нужно от машины

- Linux или любая система с `bash`, git 2.31+ и `/proc` (по `/proc/meminfo`, `/proc/loadavg`, `/proc/stat` диспетчерская меряет память и нагрузку; без `/proc` машина мест не получает). macOS пробы нет.
- `setsid` — желательно: без него отмена снимает только сам процесс команды, без его детей.
- Всё, что нужно задачам: Node, менеджер пакетов, docker и т. п.
- Вход по ключу без пароля.

## ssh

Хост в конфиге — только имя из `~/.ssh/config` (или `пользователь@имя`). Адреса, порты и ключи живут там:

```
Host build-box
  HostName build.example.com
  User ci
  IdentityFile ~/.ssh/id_ed25519
  ControlMaster auto
  ControlPath ~/.ssh/cm-%r@%h:%p
  ControlPersist 10m
```

`ControlMaster auto` держит одно соединение: проба здоровья идёт каждые 8 с, и без мультиплексирования каждая — новое рукопожатие. Встроенный в Windows OpenSSH мультиплексирование не поддерживает — там эти три строки не нужны.

Проверка: `ssh build-box true` без вопросов, затем `node setup.mjs doctor --net`.

## Конфиг

```json
"modules": { "machines": true },
"machines": {
  "local": { "workers": 2, "lanes": ["main"] },
  "build": {
    "label": "Сервер сборки",
    "ssh": "build-box",
    "dir": "~/dk/demo-shop",
    "workers": 3,
    "lanes": ["main", "db"],
    "prepare": ["npm ci --prefer-offline"]
  }
},
"tasks": {
  "api-test": { "label": "API: тесты", "run": "npx jest {input}", "input": { "label": "шаблон" }, "cwd": "apps/api", "lane": "db", "parser": "jest" }
}
```

- `ssh`, `dir` — обязательны у удалённой машины. `dir` — папка репозитория на машине (`~/…` — от домашней); создаётся при первом прогоне.
- `workers` — сколько прогонов машина ведёт одновременно (мест).
- `lanes` — какие дорожки задач машина берёт; без `lanes` — любые. Дорожка задачи — `tasks.*.lane`, по умолчанию `main`. Задачу, дорожку которой не обслуживает ни одна машина, проверка конфига отметит.
- `prepare` — команды перед **каждым** прогоном в папке прогона.
- `services` — службы для тестов, см. [отдельный рецепт](test-services.md).

## Как идёт прогон

1. Место выбирается так: сначала удалённые машины, эта — последней. Машина без свежей пробы (старше 20 с) или «не на связи» мест не даёт.
2. Снимок папки слота — вместе с несохранёнными правками; ветка и индекс слота не меняются.
3. `git push` снимка на машину, в служебную ссылку `refs/dispatcher/<слот>-p<место>`.
4. Папка прогона `<dir>-wt/<слот>-p<место>` — git worktree на этом коммите. Следующий прогон того же места переиспользует её: `checkout -f` и `clean -fd` без `-x`, поэтому `node_modules` и прочее из `.gitignore` сохраняются.
5. `prepare` → службы → команда задачи. Вывод идёт потоком в лог прогона; итог — код возврата.
6. Код 255 — не прошёл ssh: машина помечается сбоем, прогон встаёт в очередь заново.

В окружении команд: `DISPATCHER_MACHINE`, `DISPATCHER_PLACE`, `DISPATCHER_SLOT`, `DISPATCHER_JOB`.

Поезд берёт место той же очередью, что и задачи, — в дорожке своей первой проверки, после всех задач. Слияние веток в папку поезда идёт на этой машине. Если место дала удалённая машина, туда уходит дерево поезда (под ключом `regress-train`), и проверки состава идут там одной командой. Если место дала эта машина, проверки идут здесь: подготовка папки поезда (`slotPrepare`), гарды и регресс, службы `machines.local.services`.

## Своя команда на машине: `remoteCmd`

По умолчанию на машине выполняется та же команда задачи (ввод в кавычках sh, с `cd` в `cwd` задачи). Если там нужна другая — функция в `dispatcher.project.mjs`:

```js
// dispatcher.project.mjs
export function remoteCmd(taskId, input, task) {
  if (taskId === "api-test") return `cd apps/api && npx jest --ci --maxWorkers=2 '${input.replace(/'/g, "'\\''")}'`
  return null // остальным — команда задачи как есть
}
```

Возвращает строку для `bash -c` или пустое значение — тогда идёт команда задачи. Ввод подставляйте сами и в кавычках: функция получает его как есть.

## Подводные камни

- **`prepare` должен быть идемпотентным.** Штампа «уже подготовлено» нет: команды идут перед каждым прогоном. `npm ci --prefer-offline` на тёплом кэше — секунды; полная пересборка — нет.
- Зависимости и сгенерированное должны быть в `.gitignore` проекта: неотслеживаемое и не игнорируемое `clean -fd` удаляет перед каждым прогоном.
- Номер процесса прогона пишется в `/tmp` машины.
- Модуль выключен (`modules.machines: false`) — машины из конфига не используются, всё идёт на этой.
- Полного прогона «по частям» на несколько машин нет: задачи идут по одной через места.
