# Подготовка слота и сборка ветки

## Когда нужно

Слот — свежая рабочая копия (git worktree) от `staging`. В ней нет зависимостей, сгенерированного кода, локальных файлов окружения. Пока их нет, агент слота не сможет запустить ни сборку, ни тесты. Подготовка делается один раз, при создании слота; сборка ветки — когда правка касается областей, которым она нужна.

## Шаги в конфиге: `slotPrepare`

```json
"slotPrepare": [
  { "run": "npm ci --prefer-offline" },
  { "run": "npm run build --workspaces --if-present", "when": "build" }
]
```

- Шаги выполняются по порядку в папке слота, строкой в оболочку: `cmd.exe` на Windows, `/bin/sh` на Linux и macOS. Без кавычек `sh` спотыкается о скобки (`node -e process.exit(3)` — синтаксическая ошибка, код 2): такие аргументы берите в двойные кавычки (`node -e "process.exit(3)"`) — эта запись работает в обеих оболочках. Первый упавший шаг останавливает подготовку.
- `when: "always"` (по умолчанию) — всегда; `when: "build"` — только если у области слота `build: true` в `areas`.
- Слот готовится сам, когда появляется в реестре эпика (`epic.mjs add-slot`, навык `/new-slot`, кнопка на странице). Вручную — `node scripts/dev/slot-up.mjs <слот>`; флаги `--reuse` (папка уже есть), `--no-prepare`, `--no-build`, `--dry-run`.
- Журнал шагов — вне папки слота: `<папка слотов>/_logs/slot-up-<слот>.log`.
- Слот только для чтения (разведка, `add-slot --read-only`) не готовится.

## Функция `slotPrepare`

Когда шаги зависят от области, от того, свежая ли папка, или нужно что-то, кроме команд оболочки, — функция в `dispatcher.project.mjs`. Она зовётся после шагов конфига:

```js
// dispatcher.project.mjs
import fs from "node:fs"
import path from "node:path"

export function slotPrepare({ slot, dir, branch, area, main, fresh, record, project }) {
  // локальные настройки тестов не лежат в git — берём из основной папки проекта
  const src = path.join(main, "apps/api/.env.test")
  if (fresh && fs.existsSync(src)) fs.copyFileSync(src, path.join(dir, "apps/api/.env.test"))
  // ещё шаги — строками или { run }: выполнятся так же, как шаги конфига
  return area === "api" ? ["npm run db:generate --workspace apps/api"] : []
}
```

Аргументы: `slot` — имя слота, `dir` — папка слота, `branch` — ветка волны, `area` — область, `main` — основная папка проекта, `fresh` — папка только что создана, `record` — запись слота в реестре эпика, `project` — нормализованный конфиг. Функция может быть `async`. Исключение отмечает подготовку красной.

## Сборка ветки: задача `build` и функция `buildSteps`

Станция «Сборка» нужна, только если правка касается областей с `build: true`. Чем собирать — два способа:

- задача `build` в `tasks` — одна команда для всех областей;
- функция `buildSteps(dir, changed)` в `dispatcher.project.mjs` — шаги по списку изменённых файлов ветки (против точки ответвления от `staging`, вместе с новыми файлами). Возвращает список строк или `{ run, cwd? }` (`cwd` — относительно папки слота); пустой список или `null` — собирать нечего.

```js
export function buildSteps(dir, changed) {
  const steps = []
  if (changed.some((f) => f.startsWith("packages/"))) steps.push("npm run build --workspace packages/core")
  if (changed.some((f) => f.startsWith("apps/api/"))) steps.push({ run: "npm run build", cwd: "apps/api" })
  return steps
}
```

С функцией `buildSteps` станция «Сборка» считает шаги по ней, а не по флагам областей.

## Подводные камни

- **Подготовка не должна менять отслеживаемые файлы.** После шагов диспетчерская смотрит `git status`: правка отслеживаемого файла — провал подготовки. Ставьте зависимости командами, которые не трогают lock-файл (`npm ci`, `pnpm install --frozen-lockfile`, `yarn install --immutable`), а сгенерированное держите в `.gitignore`.
- Копии файлов окружения должны быть в `.gitignore` проекта, иначе они попадут в коммит слота. Агенту слота чтение `**/.env` и `**/.env.*` закрыто базовыми запретами — тестам, которые запускает диспетчерская, это не мешает.
- Подготовка идёт на этой машине. Для удалённых машин прогонов — свой `prepare` (см. [удалённая машина](remote-machine.md)).
- Тяжёлая подготовка на каждый слот складывается: пять слотов — пять установок зависимостей. Помогает кэш менеджера пакетов (`--prefer-offline`) и разумный `limits.slots`.
