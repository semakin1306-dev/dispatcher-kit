# Новый эпик: ветка и папка оркестратора, слоты, вкладка

Эпик = оркестратор (своя ветка `dev/epic-<id>` и папка) + исполнители: слоты (ветка волны и папка на слот) или поезда областей (слот с очередью волн-вагонов). Всё хранится в реестре эпиков `<папка слотов>/_epics/epics.json`; его читают диспетчерская (вкладки эпиков) и её команды. Реестр правит только команда эпиков:

```
node <дом диспетчерской>/scripts/dev/epic.mjs <команда>
```

Руками `epics.json` не редактируй. Справка по командам — та же команда без аргументов; там же перечислены области проекта.

## Сначала — ретро прошлого эпика

Если включён модуль ретро, после закрытия эпика в бэклоге появляются карточки `BL-NNNN` с полем `retro: <эпик>`. Пока у карточек ретро последнего закрытого эпика нет решения, `epic.mjs new` и `add` откажут. Поэтому первым делом:

1. `node <дом диспетчерской>/scripts/dev/backlog.mjs triage` — карточки без решения (код 0 — разбирать нечего).
2. Покажи владельцу список одним сообщением: по каждой карточке — «берём» (в какой эпик или волну) или «отказ» и почему. Рекомендацию дай, решает владелец.
3. По ответу: «берём» — `backlog.mjs set BL-NNNN status=planned epic=<id>`; «отказ» — `backlog.mjs set BL-NNNN --status rejected --reason "причина одной строкой"`.
4. `--skip-retro` у `epic.mjs new` — только если владелец прямо сказал завести эпик без разбора (диспетчерская запишет событие `retro.skip`). Сам этот флаг не ставь.

## Быстрый режим (`/new-epic <название>`)

Если владелец дал название (и, может быть, список волн) одной фразой, интервью не нужно:

1. `epic.mjs new --id <латиница-дефис> --title "<Короткое имя: подзаголовок>" --dry-run`, затем без `--dry-run`. `--activate` — только если эпик должен открываться по умолчанию (диспетчерская ведёт все открытые эпики). Команда создаст папку оркестратора от `staging` и запись в реестре; вкладка появится сама.
2. Для каждой названной волны — `epic.mjs add-slot --epic <id> --title "<имя волны>" --area <область>` (подробности — навык `new-slot`). Волн не названо — эпик остаётся без слотов, волны добавятся позже.
3. Файлы плана эпика (`_EPIC-<id>.md`, `MASTER-<id>.md` в `.claude/plans/waves/` папки эпика) заведи по образцу прошлого эпика; решения за владельца не придумывай.

Полный порядок ниже — когда эпик большой, волн много или области неясны.

## Слоты или поезда

Волны можно вести **слотами** (слот на волну, параллельно) или **поездами областей**. Поезд — обычный слот области внутри эпика с очередью волн-вагонов: метка Т1…, ветка `dev/tr-<область>-<эпик>`, одна папка, одна сессия агента. Вагоны идут строго по одному, как волна слота: станции (сборка, гарды, тесты, ревью, регресс), коммит со строкой `Wave:` вагона, влив в staging (автовливом, если он включён, иначе по слову владельца). После влива ветка поезда подтягивает staging, и агент в той же сессии получает следующий вагон. Поезд выгоден, когда волны одной области идут друг за другом (общие файлы, цепочка зависимостей); независимые волны быстрее параллельными слотами. Поезд закрывается вместе с эпиком. Области поездов — области проекта из `dispatcher.project.json` (их печатает `epic.mjs` без аргументов).

Как раскладывать вагоны по поездам:

- По каждому вагону — список файлов и модулей, которые он тронет (из раздела «Что было» и манифеста плана).
- Вагоны, которые правят **общие файлы** или зависят друг от друга по коду, — в **один поезд**, по порядку зависимости.
- Вагоны **без общих файлов** — в **разные поезда**, даже если область одна (второй поезд области — `tr-<область>2-<эпик>`): так они едут параллельно. Поездов — до 10 на эпик.
- Поезд — не больше 3–4 вагонов; длинная цепочка зависимых — один поезд, остальное раздай по другим.
- Вагон, который ждёт `after` другого поезда, держит весь свой поезд: ставь его в очереди как можно позже.
- Связь между поездами — `--after WV-NNNN@ТN`; без неё поезда друг друга не ждут.
- Вагоны, которые должны выйти в прод только в своё окно, в очередь сразу не ставь — добавь `add-wagon --wave NNNN --slug <имя файла плана>`, когда окно подойдёт: влив в staging везёт вагон в следующий релиз.

Поездами:

1. В интервью разложи волны по поездам: таблица «поезд (область) ← вагоны по порядку, общие файлы, связи `after`», для каждого поезда — почему вагоны вместе или раздельно. Дождись «да».
2. Эпик — `epic.mjs new --id … --title …` (без слотов).
3. Поезда — `epic.mjs add-train --epic <id> --area <область> [--title …] --dry-run`, затем без `--dry-run`.
4. Вагоны — `epic.mjs add-wagon --epic <id> --train ТN --title "<имя волны>" [--after WV-…] [--wave NNNN] --dry-run`, затем без `--dry-run`, в порядке очереди. План `WV-NNNN-*.md` пишется заготовкой, тесты вагона — задачи области поезда. Проверка: `epic.mjs trains --epic <id>`.
5. План каждого вагона доведи по навыку `wave-plan`.
6. В MASTER эпика — таблица поездов и вагонов. Папку поезда поднимает диспетчерская; первый вагон стартует карточкой «Запустить слот», следующие она отдаёт агенту сама после влива прошлого.

## Полный порядок (слотами)

1. **Интервью с владельцем — одним сообщением с вопросами:** название и цель эпика; список волн (номера и названия, если есть); у каждой волны — область проекта и тесты по умолчанию (задача и фильтр: задачи — в `tasks` конфига проекта, задачи области ставятся сами). Предложи таблицу слотов (метка П1…, имя папки, ветка `dev/wv-NNNN-<слово>`, область) и дождись «да».
2. **Проверь занятость имён.** Имя слота (папка в папке слотов) и ветка не должны существовать: `git branch --list "dev/wv-NNNN*"` в основной папке проекта. Имена слотов уникальны по всем эпикам.
3. **Файлы плана** (в папке эпика после её создания, на шаге 5): `.claude/plans/waves/_EPIC-<id>.md` и `MASTER-<id>.md` — цель, волны, зависимости, открытые решения владельца, таблица слотов. Решения за владельца не придумывай — помечай «решение владельца». Общие правила сессий слотов — `.claude/plans/waves/agent-briefs/SESSIONS-common-rules.md` папки эпика. **Если этот файл уже есть в репозитории проекта** (папка эпика ответвлена от staging) — это база правил проекта: НЕ заменяй его шаблоном и не переписывай, только допиши или обнови раздел «Правила эпика» (и «Известное, не чинить»). Копию шаблона `<дом диспетчерской>/agent-briefs/SESSIONS-common-rules.md` клади, только если файла нет; тогда допиши разделы эпика, а «Первые шаги» и «Проверки» не меняй (подготовку папки и проверки делает диспетчерская; устаревшие строки она найдёт сама и попросит переписать).
4. **Файл заявки** (вне репозитория проекта, например `<папка слотов>/_epics/new-<id>.json`):
   ```json
   { "id": "<латиница-дефис>", "title": "Короткое имя: подзаголовок",
     "orchBranch": "dev/epic-<id>",
     "slots": [ { "slot": "wvNNNN-<слово>", "title": "WV-NNNN <название>", "branch": "dev/wv-NNNN-<слово>", "area": "<область>",
                  "presets": [ { "task": "<задача>", "input": "wv-NNNN" } ] } ] }
   ```
   В заявке `presets` сами не ставятся (в отличие от `add-slot`): без них у слота нет тестов волны. Пресет — только фильтр, под который спека уже есть; спеки нет — пустой список.
   Проверка без побочных действий: `epic.mjs add --file <файл заявки> --dry-run`.
5. **Заведи эпик:** `epic.mjs add --file <файл заявки>` — папка оркестратора от `staging` и запись в реестре.
6. **Папки слотов поднимет диспетчерская сама** (worktree и шаги подготовки из конфига проекта), этапы видны на её странице. Ручной `node <дом диспетчерской>/scripts/dev/slot-up.mjs <слот> --branch <ветка>` — только если диспетчерская не запущена: иначе он соревнуется с её подготовкой.
7. **Активный эпик и запреты слотов:** `epic.mjs activate <id>` — если эпик должен открываться по умолчанию. Запреты слотов диспетчерская пишет сама шагом подготовки; руками (если папки поднимались без неё) — `node <дом диспетчерской>/scripts/dev/slot-workspaces.mjs --epic <id>`.
8. **Покажи владельцу итог:** вкладка эпика на странице диспетчерской (`http://127.0.0.1:<порт>`, по умолчанию 4777), список слотов с ветками и папками. Агентов слотов запускают карточки «Запустить слот» или оркестратор.

## Сначала планы и контракты

Слоты запускаются, когда готовы планы всех волн, а не по мере их написания: слот, стартовавший на плане-заготовке, строит на устаревшем контракте и переделывает.

1. Планы всех волн заполнены по навыку `wave-plan`. Агента слота с планом-заготовкой диспетчерская не запустит: передача подождёт плана.
2. Общее между волнами — контрактами, одинаковым текстом в планах обеих сторон: имена полей и таблиц, заголовки, коды ошибок, кто правит общий файл, порядок влива (`epic.mjs after ПN ПM,ПK`).
3. Вопросы владельцу по планам — одним пакетом до запуска слотов.

## Чего не делать

- Не коммитить, не пушить, не вливать в `staging`, не выкатывать. Файлы плана остаются в папке эпика незакоммиченными до слова владельца.
- Не удалять и не пересоздавать ветки и папки существующих эпиков.
- Не править `epics.json` и конфиг проекта руками ради эпика: реестр — только через `epic.mjs`.
- Не запускать тесты и сборку слотов: их ставит диспетчерская.
- Не заводить слоты с именами, занятыми другим эпиком.
- Не коммитить планы в ветку эпика без слова владельца: коммиты впереди staging останавливают перемотку папки эпика и мешают его закрытию.

## Ответ владельцу

Один блок: id эпика, слоты или поезда (метка, папка, ветка), что создано, какие решения владельца остались открытыми, адрес вкладки.
