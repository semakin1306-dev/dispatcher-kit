# Новая волна (слот) в эпик

Весь механизм — в команде эпиков:

```
node <дом диспетчерской>/scripts/dev/epic.mjs add-slot …
```

Не пиши одноразовых скриптов и не правь реестр `epics.json` руками: его правит только `epic.mjs` (прошлое состояние он сам кладёт в `epics.json.prev`). Диспетчерская подхватывает новый слот за несколько секунд; перезапускать её не нужно.

## Порядок

1. **Понять волну из слов владельца:** короткое имя (3–7 слов), область, источник (кто и что просил). Области — области проекта из `dispatcher.project.json`; `epic.mjs` без аргументов печатает их список. Область неочевидна — выбери по смыслу (по путям, которые волна тронет) и назови выбор в ответе. В проекте одна область — её можно не называть. Волна только читает код (разведка, исследование) — `--read-only`: такому слоту не нужны сборка, тесты и влив. Вопросы задавай, только если без ответа нельзя (какой эпик, если их несколько и не сказано).
2. **Эпик определяется так:** `--epic <id>` → папка, из которой запущена команда (окно оркестратора эпика) → активный эпик. Сухой прогон первой строкой печатает «эпик: <id> (почему)» — сверь.
3. **Сухой прогон:** `epic.mjs add-slot --title "<имя волны>" --area <область> --dry-run`. Проверь номер WV, имя слота, ветку и метку. Номер волны ищется сам по реестру, планам и веткам `dev/*`; владелец назвал номер — `--wave NNNN`. Транслит имени вышел кривым — `--slug latin-name`. Волна строится на коде другой, ещё не влитой волны — `--after ПN`: диспетчерская не даст влить её раньше. Порядок влива позже ставит оркестратор строкой `ПОРЯДОК ПM ПОСЛЕ ПN` (то же, что `epic.mjs after ПM ПN`).
4. **Тесты волны (пресеты).** По умолчанию — задачи области (`areas.<область>.tasks` конфига); задаче с вводом подставляется номер волны (`wv-NNNN`). **Пресет — только фильтр, под который в слоте есть спека** (проверь `git ls-files | grep <фильтр>`): фильтр наугад даёт «нет тестов» и держит станцию «Тесты» красной. Спеки ещё нет — очисти: `epic.mjs presets ПN -`; набор поставит оркестратор или слот после разведки. Поменять: `epic.mjs presets ПN <задача>=<фильтр> …` (без списка — показать; задачи — из `tasks` конфига).
5. **Создать:** та же команда без `--dry-run`. Она запишет заготовку плана `WV-NNNN-<слово>.md` в папку оркестратора эпика и добавит слот в реестр. Дальше диспетчерская сама, для любого открытого эпика: поднимает папку слота (worktree и шаги подготовки из конфига), собирает стартовый промпт из персоны и плана волны и выкладывает карточку «Запустить слот». Если диспетчерская не запущена, команда сама вызовет `slot-up.mjs` — дождись вывода и не запускай параллельно другие `slot-up`.
6. **Доведи план по навыку `wave-plan`:** источник, «что было» (по коду, а не по памяти), решения Р1… «предложены, подтвердить», станции с красным тестом, манифест слота, «не делаем». Решения владельца не выдумывай. Слоту нужен общий файл — так и напиши в манифесте: правит оркестратор.
7. **Команда упала на worktree:** слот уже в реестре; повтори `node <дом диспетчерской>/scripts/dev/slot-up.mjs <слот> --branch <ветка>` и сообщи причину.

Что дальше делают слот и диспетчерская (для ответа владельцу): слот проходит станции плана подряд в одном ходе и докладывает один раз; сборку, гарды, тесты, ревью, регресс и коммит ведёт диспетчерская; влив в staging — автовливом, если он включён (станции зелёные, ревью «ЗА», агент доложил «ГОТОВО», конфликта нет), иначе `ВЛИТЬ ПN` по слову владельца. Выкат стенда и релиз — только словом владельца.

## Эпик с поездами: новая волна = новый вагон

Если в эпике есть поезда (метки ТN; `epic.mjs trains --epic <id>`), новая волна **не заводит слот**, а встаёт вагоном в очередь поезда своей области:

1. Поезд — по манифесту волны: пересечение со `scope` поезда и его областью; при равенстве — поезд с короткой очередью. Поезда нужной области нет — `epic.mjs add-train --area <область>`.
2. `epic.mjs add-wagon --train ТN --title "<имя волны>" [--after WV-…|WV-…@ТM] [--wave NNNN] --dry-run`, затем без `--dry-run`: заготовка плана пишется так же, как у `add-slot`, вагон встаёт в конец очереди; тесты вагона — задачи области поезда (поменять — `epic.mjs presets WV-NNNN <задача>=<фильтр>`).
3. Порядок очереди — `epic.mjs order-wagons ТN WV-… WV-…`; перевести вагон в другой поезд — `epic.mjs move-wagon WV-… --to ТM`; снять — `epic.mjs remove-wagon WV-…` (только не начатый вагон: без коммитов и не выданный агенту).
4. Срочная волна — отдельный поезд из одного вагона, только по слову владельца.

Дальше диспетчерская сама: когда прошлый вагон вольётся в staging, ветка поезда подтянет staging и агент поезда получит этот вагон в своей сессии.

## Волна уже есть в другом эпике

Владелец переносит существующий слот (с веткой, папкой и работой) в этот эпик — нового слота не заводи (`add-slot` откажет на занятой ветке). Перенос: `epic.mjs move-slot <ПN|слот> --from <старый эпик> --to <этот эпик> --dry-run`, затем без `--dry-run`. Имя слота, ветка, папка, пресеты и история заданий сохраняются; меняются метка и цвет; план `WV-NNNN-*.md` копируется в папку оркестратора нового эпика. Снять слот из реестра, не трогая ветку и папку, — `epic.mjs remove-slot <ПN|слот> --epic <эпик>`.

## Чего не делать

- Не коммитить, не пушить, не вливать, не выкатывать. План и реестр остаются незакоммиченными до слова владельца; планы в ветку эпика без нужды не коммить — коммиты впереди staging останавливают перемотку папки эпика и его закрытие.
- Не запускать тесты и сборку слота руками: их ставит диспетчерская.
- Не создавать ветку и папку руками мимо `epic.mjs` и не править `epics.json`.
- Не перезапускать диспетчерскую.

## Ответ владельцу

Один блок: волна (номер, имя), слот (метка, цвет, папка, ветка) или вагон (поезд, место в очереди), путь к плану, какие решения подтвердить, что дальше — карточка «Запустить слот» (или оркестратор запустит слот сам).
