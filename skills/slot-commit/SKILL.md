# Коммит волны силами агента слота

Агент слота коммитит в **своей** ветке. Когда — решает режим коммитов, о котором говорит подсказка диспетчерской:

- «после каждой станции» — сам, один коммит на законченную станцию плана;
- «по усмотрению» — сам, когда кусок работы закончен;
- «только по слову» — без сообщения «Владелец нажал кнопку «Коммит»» не коммить.

Коммит — не выкат: влив в staging делает диспетчерская (автовливом после твоего «ГОТОВО» или по слову владельца), выкат стенда и прода — только владелец. Сообщение «Владелец нажал кнопку «Коммит»» означает коммит остатка в твоей ветке.

## Когда

- После каждой законченной станции плана (ST0, ST1, …), если режим это разрешает.
- Перед докладом «ГОТОВО»: рабочее дерево чистое, всё своё закоммичено. Промежуточный коммит волну не замораживает — проверки диспетчерская ставит, пока ты не доложил «ГОТОВО».
- По сообщению «Владелец нажал кнопку «Коммит»» — коммит того, что осталось.

## Шаги

1. **Где ты.** `git branch --show-current` и `git status --porcelain --untracked-files=all` в папке слота. Ветка должна быть `dev/wv-…` (твоя ветка волны) или `dev/tr-…` (слот-поезд: в одной ветке по очереди едут волны-вагоны; номер — вагона, который ты сейчас ведёшь). Если это `staging`, `main` или отсоединённая голова — остановись и сообщи.
2. **Что входит.** Только файлы этой волны (этой станции). Не включай: `.env*`, ключи и токены, отчёты и результаты тестов, `*.log`, кеши и сборочные артефакты, файлы, которые менял не ты и не твоя волна. Сомнительный файл не добавляй, а назови в докладе.
3. **Сгенерированное вместе с правкой.** Если правка порождает артефакты, которые проект хранит в git (миграции и снимки схемы, lock-файл зависимостей, сгенерированные типы), они идут в том же коммите, что и правка.
4. **Разбери правки.** `git diff --stat` и диф главных файлов, чтобы подпись описывала суть, а не список файлов.
5. **Подпись пиши сам**, по образцу истории (`git log --oneline -15`):
   - тема: `тип(область): WV-NNNN STn: суть` (коммит станции) или `тип(область): WV-NNNN — суть` (остаток по кнопке), один смысл, без точки в конце. Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`. Номер волны — из имени ветки; у поезда (`dev/tr-…`) — из сообщения диспетчерской о вагоне в работе, а починка уже закоммиченного вагона — номер того вагона, тип `fix`;
   - тело: 2–6 строк — что изменено и зачем, что не тронуто, если это важно;
   - честная строка о проверке: тесты гоняет диспетчерская, поэтому пиши итог, который видел в её выжимке прогона, иначе «тесты не запускались агентом». Не выдумывай результат;
   - **в каждом коммите** последний абзац — трейлеры: строка `Wave: WV-NNNN` (номер волны, у поезда — вагона) и, если требуют твои системные указания, строка соавторства. По строке `Wave:` диспетчерская находит границы волны и вагона, состав поезда и вагоны к приёмке; номер она сверяет с реестром. Надёжнее всего — `--trailer "Wave: WV-NNNN"`. Один коммит — одна волна (вагон): правки двух вагонов не смешивай.
6. **Коммит.** `git add <явный список путей>` — никогда `git add -A`, `git add .` и `git commit -a`. Затем `git commit` с подписью в команде: несколько `-m` (строка Wave — трейлером или последним `-m`) или `-m "$(cat <<'EOF' … EOF)"`. Только в своей папке: без `cd` в чужие папки и без `git -C`. Хуки не обходи (`--no-verify` запрещён); упал хук — найди причину и исправь.
7. **Проверь результат.** `git log -1 --stat` и `git status --short`: что осталось незакоммиченным и почему.

## Чего не делать

- Не пушить, не делать `merge` (кроме слияния staging по указанию диспетчерской), `rebase`, `reset`, `amend` чужих коммитов, не переключать ветки.
- Не трогать `staging`, `main` и чужие ветки слотов.
- Не запускать тесты и сборку: их ставит диспетчерская.
- Не вливать в staging и не выкатывать.

## Ответ

Коммит станции — без отдельного доклада: иди к следующей станции, в итоговом докладе хода перечисли коммиты строкой «Закоммичено: <хеши>». По кнопке «Коммит» — одним блоком:

```text
КОММИТ <короткий хеш> <тема коммита>
Файлов: <N>. Сгенерированное: <что, или «нет»>.
Не включил: <файл — причина> (или «ничего»).
Осталось не закоммичено: <что> (или «ничего»).
Дальше: влив в staging — диспетчерская или слово владельца.
```
