# Статус поездов

Поезд (метка ТN) — обычный слот области с очередью волн-вагонов. Вагоны идут строго по одному: вагон ветки проходит станции как волна слота, вливается в staging (автовливом, если он включён: станции зелёные, ревью «ЗА», агент доложил «ГОТОВО», конфликта нет; иначе по слову владельца), после влива ветка подтягивает staging и агент в той же сессии получает следующий вагон.

1. Запусти отчёт (только чтение — API диспетчерской и её журнал событий):
   `node <дом диспетчерской>/scripts/dev/trains-status.mjs --epic <id эпика>` (без `--epic` — все эпики; `--since 180` — журнал за 3 часа; `--json` — для разбора).
   Id эпика не назван — возьми открытый эпик с поездами (`node <дом диспетчерской>/scripts/dev/epic.mjs list`). Очередь по git без диспетчерской: `node <дом диспетчерской>/scripts/dev/epic.mjs trains --epic <id>`.
2. Перескажи владельцу коротко, без кодов задач там, где можно:
   - **Едет:** по каждому поезду — вагон ветки и его станция (у агента, на проверках, ждёт влива), что уже влито, кто следующий в очереди.
   - **Стоит:** что не движется и почему (строка «дальше», ждёт агента, красный прогон, отказ ворот, голова очереди ждёт вагон другого поезда). «Можно вливать» или «Запустить вагон» при пустой очереди прогонов — шаг за владельцем или за тобой (по его слову).
   - **Приёмка** (если включена): по вагонам — пунктов, авто ✓/✗, вердикт; без спеки — помечено.
   - **Ждёт владельца:** вопросы агентов — суть и рекомендованный вариант.
   - **Смотреть:** события из раздела «События, на которые смотреть» (повторяющиеся отказы ворот, `train.issue.held` — следующий вагон не выдан и почему). Если они указывают на сбой самой диспетчерской — скажи и предложи правку.
3. Не запускай прогоны, вливы и выкаты из этого навыка — только отчёт. Ветка «готова, но не влита» при включённом автовливе — найди причину: события `merge.auto.refused` (какая проверка влива отказала), `slot.sync.auto` (конфликт отдан агенту), нет «ГОТОВО» агента. Действовать — по отдельному слову владельца.
